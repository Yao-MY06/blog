> **一句话记住**：先用 zread 看地图（5分钟知道这山有啥），再 recursive 挖矿（遇到不懂的立刻跳出去学），最后**强制写一行代码**（不动手等于白看）。
>
> **解决你最大的痛点**：看懂架构就很累 → 因为你在用"上课模式"读代码；项目式学习是"盗墓模式"——带张地图下去，挖到宝贝就撤，遇到机关当场学，不累。

## 一、你的现状诊断

| 你说的问题 | 根本原因 | 解法 |
|-----------|---------|------|
| "看懂架构已经很费劲" | 你在试图"上课式"从头到尾理解整个项目 | 改为"寻宝式"——只挖你需要的部分 |
| "很难动手去做" | 看完代码觉得"看懂了"，动手时发现不知道怎么开始 | 看完立刻强制写一行，不写不让关电脑 |
| "递归式学习很爽" | 你的大脑喜欢"遇到问题→解决问题"的正反馈 | 把它变成系统化流程，不要随缘 |
| "上课学半天才到一个知识点" | 被动接收 vs 主动搜寻的区别 | 用 zread 当搜索引擎，只看你要的 |

## 二、工具链：zread.ai + DeepWiki 怎么用

### 两个工具的分工（别只用其中一个）

| 场景 | 用哪个 | 怎么用 |
|------|--------|--------|
| **第一次接触项目，完全陌生** | **zread.ai** | 粘贴 GitHub 链接，生成中文结构化手册，先看"概览"和"如何快速上手" |
| **想深挖某个模块的架构设计** | **DeepWiki** | 替换 github.com 为 deepwiki.com，直接问"这个模块为什么这么设计？" |
| **看到项目用了某个不懂的技术（如 decorator）** | **两者都不要用** | 去 B站/文档直接搜 decorator 用法，这是递归学习，不是项目阅读 |
| **准备面试/写简历，需要讲项目架构** | **zread → DeepWiki** | zread 建立全貌 → DeepWiki 追问细节 → 自己画一张架构图 |

### zread.ai 实操步骤（3分钟上手）

```
1. 找到一个想学的开源项目（比如 React、某个后台管理系统）
2. 复制 GitHub 链接
3. 打开 zread.ai，粘贴链接（或直接把 github.com 换成 zread.ai）
4. 看三个东西（只看这三个，不要精读）：
   ├─ 项目概览：这项目是干嘛的？解决了什么问题？
   ├─ 文件树：代码怎么组织的？入口在哪？
   └─ 核心模块：最关键的几个文件/文件夹是哪些？
5. 时间控制：5-10 分钟，看完就关。不要细读！
```

### DeepWiki 实操步骤（深度追问）

```
1. 在 zread 看完全貌后，对某个模块感兴趣（比如"这个路由系统怎么设计的？"）
2. 把 github.com 换成 deepwiki.com，进入同一个项目
3. 直接提问（用自然语言）：
   - "用户登录流程涉及哪些文件？"
   - "这个函数为什么用工厂模式？"
   - "数据库迁移是怎么触发的？"
4. DeepWiki 会定位到具体代码行，给你解释
5. 时间控制：15-20 分钟，解决具体问题就停
```

### 最佳组合姿势

```
Step 1（zread）：5分钟建立全貌
    ↓
Step 2（你）：选一个"我想实现的功能"（比如：这个项目的登录是怎么做的）
    ↓
Step 3（DeepWiki）：10分钟定位相关代码
    ↓
Step 4（你）：递归学习——遇到不懂的语法/概念，立刻跳转学习
    ↓
Step 5（强制）：不看更多代码，先写一版自己的实现
    ↓
Step 6（对比）：写完后回头看原项目，对比差距
```

## 三、PRACTICAL 项目式学习流程

> 7 个字母，每一步都有明确的"你做"和"AI 做"。

### P - Pick（选项目）

**你做的**：
- 选一个跟你**当前主线相关**的项目（不要杂学）
  - 全栈阶段：选一个全栈后台管理项目（如 ant-design-pro、realworld 等）
  - UE5 阶段：选一个 Lyra/ALS 相关的开源插件或社区项目
- 标准：Star 数 500+，最近 3 个月有更新，有 zread/DeepWiki 索引

**AI 辅助**：让 zread 生成项目概览，判断"这个项目值得学吗？"（看文档是否清晰、issue 是否活跃）

---

### R - Read map（读地图）

**你做的**：
- zread 5 分钟看完全貌
- 在白纸上（或 Excalidraw）画一张**极简架构图**：
  ```
  [用户] → [前端页面] → [API路由] → [数据库]
            ↓              ↓
         [组件库]      [认证中间件]
  ```
  不要多，5 个框以内。

**AI 辅助**：zread 生成文件树和模块关系，你只管理解连线关系

**验收标准**：能不看文档，说出"这个项目最核心的 3 个文件夹是干嘛的"

---

### A - Aim（定靶子）

**核心原则**：不要试图"学完整个项目"，只学**一个最小功能**。

**你做的**：
- 从项目中选一个你"今晚就要实现"的功能：
  - 不要选："整个用户系统"
  - 要选项："用户登录时的表单验证是怎么写的"
  - 要选项："这个项目的 404 页面是怎么处理的"
  - 要选项："这个 API 的错误返回格式统一封装在哪里"

**AI 辅助**：可以问 DeepWiki "这个项目里登录功能涉及哪些文件？" 快速定位靶子

---

### C - Copy & Carve（抄与改）

**你做的**：
1. 把目标功能的代码**抄到自己项目里**（不要看懂再写，先抄）
2. 运行，看看能不能工作
3. **删掉一半**，看哪些是必须的
4. **改一个参数/换一个变量名**，看会发生什么

**AI 辅助**：
- 卡住了让 AI 解释这行代码
- 报错时让 AI 分析（但不要直接要答案，要诊断思路）

**关键心法**："先让代码跑起来，再理解它为什么跑起来"

---

### T - Traverse recursive（递归穿梭）

> 这是你最爽的部分，系统化它。

**触发条件**：看到任何"不懂的东西"——语法、函数、库、设计模式

**你的动作**：

```
看到 decorator（@login_required）
    ↓
【立刻停】不要继续往下读项目代码
    ↓
【跳转】打开 B站/文档/AI，搜"Python decorator 10分钟入门"
    ↓
【只学最小够用】不需要精通 decorator 的所有用法
    ↓
    只需要回答三个问题：
    1. decorator 是干嘛的？（包装函数）
    2. 语法长什么样？（@xxx 在函数上面）
    3. 这个项目里它用来干嘛？（登录检查）
    ↓
【立刻回来】回到项目代码，继续读
    ↓
【标记】在笔记里写"decorator：学过，用在登录验证"
```

**时间控制**：每个递归点最多 15 分钟。15 分钟还没懂？先标记"TODO：深挖"，继续往下走。不要死磕。

**AI 辅助（L1 本地即可）**：
- 问"这个语法是干嘛的？"
- 问"这个项目里的 decorator 为什么这么用？"
- 生成一个最小示例跑通

---

### I - Implement（动手实现）

**核心原则**：这是不可跳过的步骤。不动手 = 没学。

**强制动手机制**：

```
看完项目代码后，不要再看任何参考。

打开你的编辑器，凭记忆写：
- 如果学的是"登录验证"：写一个你自己版本的登录验证
- 如果学的是"路由封装"：写一个你自己版本的路由
- 如果学的是"状态管理"：用你刚看的思路，管理一个小状态

规则：
1. 不看原项目代码（可以抬头看天花板）
2. 可以查语法（递归学习的成果）
3. 写 30 分钟，不管写成什么鬼样
4. 写完再打开原项目对比
```

**AI 辅助（模板 B：项目组件生成）**：
- 写完后让 AI 对比"你写的"和"原项目的"，指出差距
- 但不要 AI 直接帮你重写——重写是下一轮的输入

---

### C - Compare（对比复盘）

**你做的**：
1. 把自己写的和原项目放一起看
2. 问自己三个问题：
   - "原项目为什么比我好？"（具体点：封装更好？错误处理更全？）
   - "我有没有比原项目更简洁的地方？"（不一定原项目全对）
   - "这个设计模式我能用在当前主线的项目里吗？"

**AI 辅助**：让 AI 做 diff 分析，但**你先自己看完再给 AI 看**，不然你的大脑不参与。

---

### A - Archive（归档）

**你做的**：
- 把这次学习存入你的 Agent 资产库/知识库：

```
项目名：__________
学习的功能：__________
递归学到的知识点：__________（如 decorator、中间件、xxx库）
我动手实现了：__________
原项目比我的好在哪里：__________
我能复用的地方：__________
耗时：__________
```

**AI 辅助**：可以帮你格式化笔记，但内容必须你自己填。

---

### L - Loop（循环）

**规则**：
- 同一个项目，至少用这个方法学 **3 个不同功能**
- 每个功能间隔 1-2 天，不要一口气学完
- 3 个功能后，你对这个项目的架构自然就有了体感（不再需要 zread）

## 四、解决"很难动手"的强制机制

> 你不是不想动手，你是觉得"还没准备好"。项目式学习最大的敌人就是"准备综合征"。

### 机制 1：15 分钟强制启动

```
设一个倒计时 15 分钟的闹钟。
规则：
- 前 15 分钟，你只能做一件事：【抄代码】
- 不管懂不懂，把原项目的目标功能代码复制到你的编辑器里
- 15 分钟一到，你必须停，问自己"还想继续吗？"
- 90% 的情况你会继续，因为"抄着抄着就懂了"
```

### 机制 2：故意写烂代码

```
给自己许可："这第一版就是烂代码，没关系"
目标不是"写得像原项目一样好"
目标是"让这坨东西能跑"
跑起来之后再 refactor（重构）
原项目的优雅是第 10 版，你的第 1 版可以丑
```

### 机制 3：最小复制单元

```
不要试图"复刻整个登录系统"
今晚只复刻"密码长度验证"这一个小函数
或者"登录按钮的加载状态"这一个组件
小到你觉得"这也太简单了吧"——那就对了
```

### 机制 4：身体先于大脑

```
不要等"想明白了"再写
手指先敲，大脑后跟上
你会发现：
- 手指敲到一半，大脑突然"哦原来是这样"
- 这是项目式学习的魔法，上课学不到
```

```
┌─────────────┬─────────────────────────────────────┐

├─────────────┼─────────────────────────────────────┤
│ 模板B项目组件 │ 用 PRACTICAL 流程学一个功能 → 写代码  │
├─────────────┼─────────────────────────────────────┤
│ 模板C Bug诊断 │ 自己写时报错 → 对比原项目 → 找差异   │
├─────────────┼─────────────────────────────────────┤
│ 模板D自动化   │ 把"递归学习"中重复的查询做成 prompt  │
└─────────────┴─────────────────────────────────────┘
```

### 与路线图的联动

```
全栈路线图第3-4周：学 React
    ↓
项目式学习：选一个 React 开源组件库（如 shadcn-ui）
    ↓
PRACTICAL 流程：
  P：选 shadcn-ui
  R：zread 5分钟看架构
  A：定靶子——"Button 组件是怎么支持 loading 状态的？"
  C：抄 Button 组件到自己的项目
  T：遇到 TypeScript 泛型不懂 → 递归学 15 分钟
  I：自己写一个 Button（哪怕很丑）
  C：对比 shadcn 的 Button 和你的 Button
  A：归档笔记
  L：过两天再来学"Dialog 组件的动画是怎么做的"
```

### Token 经济

```
zread.ai：免费（项目概览）
DeepWiki：免费（具体追问）
递归学习时的 AI 问答：
  - 语法概念解释 → L1 本地（Qwen2.5 足够）
  - 代码实现辅助 → L2 轻量（GPT-4o-mini）
  - 架构对比分析 → L3 重载（每周最多1次）

省钱技巧：
- zread/DeepWiki 解决"项目理解"，不花 token
- L1 本地解决"语法递归学习"
- L2 只在你"动手写卡住"时才调用
```

## 六、一句话总结

> **项目式学习不是"读完一本书"，是"挖三个宝贝"。**
>
> zread 是你的地图（5分钟），递归是你的矿镐（遇到石头就敲），强制动手是你的出货单（不搬回家不算你的）。
>
> 别当图书馆里的学生，当盗墓笔记里的主角——带张地图下墓，摸到一个明器就撤，遇到粽子当场学怎么打。
