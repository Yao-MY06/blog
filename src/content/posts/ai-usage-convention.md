## 一、使用边界

### 1.1 适合用 AI 的场景

| 场景 | 示例 | 理由 |
|------|------|------|
| **代码生成** | 写 Controller、Service、工具类 | AI 擅长结构化代码 |
| **Bug 诊断** | 分析报错日志、定位问题 | AI 能快速识别常见问题 |
| **技术问答** | "Spring AOP 原理是什么" | AI 能快速给出解释 |
| **方案设计** | 架构设计、技术选型 | AI 能提供多种思路 |
| **长文档总结** | 总结技术文档、论文 | AI 擅长提取关键信息 |

### 1.2 不适合用 AI 的场景

| 场景 | 理由 | 替代方案 |
|------|------|---------|
| **业务逻辑判断** | AI 不了解你的业务背景 | 自己思考或请教导师 |
| **代码审查** | AI 可能漏掉边界情况 | 人工 Review 或结合工具 |
| **生产环境决策** | AI 答案可能过时或错误 | 查官方文档或咨询专家 |
| **已知的重复问题** | 浪费 token | 查自己的 `04-知识笔记/` |

## 二、Token 优化策略 ⭐⭐⭐

> **核心原则**：每个 token 都要有价值，不浪费在重复、冗余和无用的输出上。

### 2.1 技巧1：清理上下文（省50% token）

#### ❌ 错误示范
```
对话第1轮：问了 Spring Bean 生命周期
对话第2轮：问了 MyBatis 缓存机制
对话第3轮：问了 Redis 持久化
对话第4轮：问了 MySQL 索引优化

第5轮想问 Spring AOP，但 AI 仍携带前 4 轮完整历史
→ 前 4 轮内容与 AOP 无关，浪费大量 token
```

#### ✅ 正确做法
```
方法A：开新对话
- 问完 MySQL 索引后，关闭当前对话
- 问 Spring AOP 时，开启新对话
- 不携带无关历史

方法B：明确告诉 AI"忽略之前的对话"
- "忽略之前关于 MySQL 的讨论，现在我要问 Spring AOP..."

方法C：只复制相关上下文
- 如果 AOP 问题需要参考之前的 Spring Bean 讨论
- 只复制那 1-2 轮相关内容，不要全部复制
```

**预期效果**：token 消耗降低 **30-50%**

---

### 2.2 技巧2：分段请求而不是一次生成（省30% token）

#### ❌ 错误示范
```
"帮我写一个完整的用户管理模块，包括：
- UserController（增删改查）
- UserService（业务逻辑）
- UserMapper（数据库操作）
- User 实体类
- UserDTO
- 统一异常处理
- 参数校验
- 完整的注释"

→ AI 一次生成 1000+ 行代码
→ 大量 token 消耗
→ 生成的代码可能有很多你不需要的部分
```

#### ✅ 正确做法
```
第1次请求：
"设计用户管理模块的类结构，只给类名、方法签名和依赖关系，不要实现代码"

第2次请求：
"根据刚才的设计，写 UserController 的代码，包含增删改查4个接口"

第3次请求：
"写 UserService 的代码，包含业务逻辑和事务处理"

第4次请求：
"写 UserMapper 接口和 XML 配置"

→ 每次只生成需要的部分
→ 可以在生成过程中调整方向
→ 不需要的部分可以跳过
```

**预期效果**：token 消耗降低 **20-30%**

---

### 2.3 技巧3：要求简洁答案（省70% token）

#### ❌ 错误示范
```
"解释一下 Spring AOP 的原理"

→ AI 写了 3000 字的长文，包括：
  - AOP 的历史背景
  - AOP 的各种术语解释
  - 5 种不同的实现方式
  - 10 个使用场景
  - 完整的代码示例
  - 性能优化建议
  - 常见问题排查

→ 你只需要核心原理，其他 90% 的内容都是浪费
```

#### ✅ 正确做法
```
"用 200 字解释 Spring AOP 的核心原理，然后给一个最简单的代码示例（不超过 30 行）"

→ AI 只回答核心内容：
  - 动态代理（JDK 代理 vs CGLIB）
  - 切面、切点、通知的概念
  - 一个 @Around 注解的最小示例

→ 如果需要更多细节，再追问具体问题
```

**常用限定词**：
- "用 X 字以内解释"
- "只给核心原理，不要展开"
- "用最简单的例子说明，不要复杂场景"
- "只列出关键步骤，不要详细解释每一步"

**预期效果**：token 消耗降低 **50-70%**

---

### 2.4 技巧4：复用知识而不是重复问（省100% token）

#### ❌ 错误示范
```
第1周：问 AI "Maven 依赖冲突怎么解决"
第2周：又遇到依赖冲突，再问 AI 一次
第3周：又遇到依赖冲突，再问 AI 一次
第4周：又遇到依赖冲突，再问 AI 一次

→ 每次都消耗 token，但答案都差不多
→ 4 周浪费了 4 次 token
```

#### ✅ 正确做法
```
第1周：问 AI "Maven 依赖冲突怎么解决"
→ 把答案写成最小笔记，存入 `04-知识笔记/Maven依赖冲突解决方案.md`

笔记内容：
---
# Maven 依赖冲突解决方案

- 一句话理解：多个依赖引入了同一个库的不同版本，Maven 默认选最近的版本，可能导致运行时错误
- 一个例子：
  1. 用 `mvn dependency:tree` 查看依赖树
  2. 找到冲突的依赖
  3. 用 `<exclusion>` 排除不需要的版本
- 一个易错点：排除后要验证功能是否正常，有些库的不同版本 API 不兼容
- 来源：GLM Pro 对话记录 2026-09-02
---

第2周：遇到依赖冲突 → 直接打开笔记查看 → 不再问 AI
第3周：遇到依赖冲突 → 直接打开笔记查看 → 不再问 AI
第4周：遇到依赖冲突 → 直接打开笔记查看 → 不再问 AI

→ 节省了 3 次 AI 对话的 token
```

**适合写笔记的知识类型**：
- 反复出现的错误（如依赖冲突、端口占用、数据库连接失败）
- 常用的命令或配置（如 Git、Docker、Maven 命令）
- 技术概念解释（如 AOP、IoC、事务传播）
- 代码模板（如异常处理、参数校验、统一返回格式）

**预期效果**：相同问题第 2 次起 **100% 省 token**

### 2.5 技巧5：用本地工具替代 AI（省100% token）

| 场景 | ❌ 用 AI | ✅ 用本地工具 |
|------|---------|-------------|
| **格式化代码** | 让 AI 格式化 | IDEA 自动格式化（Ctrl+Alt+L） |
| **生成 Getter/Setter** | 让 AI 生成 | IDEA 自动生成（Alt+Insert） |
| **查看类的方法** | 问 AI "XX 类有哪些方法" | IDEA 按住 Ctrl 点击类名 |
| **查看依赖版本** | 问 AI "Spring Boot 当前版本" | 直接看 `pom.xml` |
| **翻译变量名** | 让 AI 翻译 | Google 翻译或有道词典 |
| **简单的正则表达式** | 让 AI 写 | regex101.com 在线测试 |

**预期效果**：这些场景 **100% 省 token**

---

### 2.6 技巧6：批量处理而不是逐个问（省时间，token持平）

#### ❌ 效率低
```
问 AI："解释 @Autowired"
问 AI："解释 @Resource"
问 AI："解释 @Qualifier"
问 AI："解释 @Primary"

→ 4 次对话，分别等待 4 次响应
```

#### ✅ 效率高
```
一次问 AI：
"用表格对比 @Autowired、@Resource、@Qualifier、@Primary 的区别，
每个注解只用一句话说明用途和典型场景"

→ 1 次对话，一次性拿到答案
→ token 消耗差不多，但效率提升 4 倍
```

## 四、风险判断

### 4.1 不要盲目相信 AI 的答案

| 场景 | 风险 | 应对 |
|------|------|------|
| **代码安全** | AI 可能生成有漏洞的代码（SQL 注入、XSS） | 代码审查 + 安全扫描工具 |
| **版本兼容** | AI 的答案可能基于旧版本 | 查官方文档确认 |
| **性能问题** | AI 的代码可能性能低下 | 压测 + 性能分析 |
| **业务逻辑** | AI 不了解你的业务 | 人工判断 + 领域专家确认 |

### 4.2 代码必须验证

AI 生成的代码必须：
1. **本地运行测试**：确保能跑通
2. **边界情况测试**：测试空值、异常、极端输入
3. **代码审查**：检查是否符合项目规范
4. **写单元测试**：确保功能正确

### 4.3 敏感信息不发送给 AI

不要把以下信息发送给 AI：
- 生产环境的数据库连接字符串
- API 密钥、Token、密码
- 用户隐私数据（真实姓名、手机号、身份证）
- 公司内部的业务逻辑和数据

**如果需要 AI 帮忙调试包含敏感信息的代码**：
- 用占位符替换敏感信息（如 `数据库密码: ******`）
- 只发送最小必要的代码片段
