## 一、为什么你需要卡片笔记

你现在的笔记方式可能是这样的：
- 看教程时记了一堆"知识点"，再也没看过
- 收藏了100篇文章，收藏夹就是坟墓
- 写了很多笔记，但它们之间没有任何联系
- "我好像学过这个"——但想不起来在哪学的

卡片笔记解决的核心问题：**让知识之间产生连接，形成网络，而不是一堆孤立的点。**

> 通常，被实际调用并连接到相关上下文的笔记更有用；具体效果需通过实际使用验证。

## 二、Zettelkasten简化版：只保留两层

传统Zettelkasten有三层（闪念笔记→文献笔记→永久笔记），太复杂。**你只保留两层：**

| 层级 | 名称 | 作用 | 何时写 |
|------|------|------|--------|
| 第1层 | **文献笔记** | 学习时记录的原始理解 | 读教程/文档/文章时 |
| 第2层 | **永久笔记** | 将分散的知识连接成概念卡片 | 每周回顾时 |

**不要闪念笔记。** 灵感来了直接写在晨间日志里，或者放收件箱当晚处理。

## 三、文献笔记：记录"我学到了什么"

### 什么时候写
- 看技术教程时
- 读文档时
- 读博客文章时
- 做完一个项目模块后

### 怎么写

**关键规则：用自己的话，不是复制粘贴。**

````markdown
## 文献笔记：React useState的工作原理

- 来源：React官方文档 - State: A Component's Memory
- 日期：2024-03-15
- 学习场景：做待办应用时需要管理待办列表状态

### 我学到了什么
useState就是一个函数，调用它传入初始值，返回两个东西：
当前值 和 一个更新函数。

调用更新函数时，React会重新渲染组件，UI更新。

### 我不太确定的地方
setState是异步的？为什么说"状态更新可能被批处理"？
→ 需要进一步学习JavaScript事件循环

### 代码示例
```jsx
const [todos, setTodos] = useState([]);
// todos是当前状态值
// setTodos是用来更新todos的函数
```
````

### 文献笔记的特点
- 一次性的、与特定学习场景绑定的
- 允许有不理解的地方（标记出来）
- 有代码示例更好
- 存在 `/04-知识笔记/文献笔记/` 中

## 四、永久笔记：将知识连接成"概念卡片"

### 什么时候写
**每周日晚，知识清理时间。** 回顾本周的文献笔记，提取可以通用的知识，写成永久笔记。

### 永久笔记的格式标准

每条永久笔记必须包含以下5个部分：

```markdown
## ID：20240318-001 | 核心概念（一句话概括）

### 详细说明
（用自己的话详细解释这个概念，不是复制粘贴）

### 我如何理解它
（类比、联想、个人经验——这是你自己的思考）

### 相关笔记
- 20240310-002-相关概念A
- 20240312-005-相关概念B

### 应用场景
- 项目X中可以用到……
- 未来学习Y时可能有关联
```

### 各部分填写说明

#### 1. 唯一ID
格式：`YYYYMMDD-序号`
- 日期 + 当天第几条笔记
- 用于唯一标识，方便在其他笔记中引用
- 示例：`20240318-001`（2024年3月18日的第1条笔记）

#### 2. 核心概念
一句话概括这条笔记的内容。将来搜索时，这句话就是你找到它的关键。

**好示例**：`JavaScript闭包是函数对其词法作用域的引用，即使外部函数已执行完毕`

**坏示例**：`JavaScript学习笔记`（太笼统，没有信息量）

#### 3. 详细说明
用自己的话解释这个概念。想象你在向一个同学解释——不是背诵定义，而是讲清楚它是什么、为什么重要、怎么工作。

#### 4. 我如何理解它
这是最重要的一部分。写下：
- 一个类比（"这就像……"）
- 一个联想（"这让我想到……"）
- 一个个人经验（"我做项目时遇到过……"）

#### 5. 相关笔记
列出与这条笔记相关的其他永久笔记的ID。这就是**反向链接**，是知识网络的核心。

#### 6. 应用场景
具体列出你在什么项目或什么情况下可能用到这条知识。让笔记与实际工作产生关联。

## 五、完整示例：理解JavaScript闭包

```markdown
## ID：20240318-001 | JavaScript闭包允许内层函数访问外层函数的作用域，即使外层函数已执行完毕

### 详细说明
闭包的本质是：当一个函数内部定义了另一个函数，内部函数持有对外部函数作用域的引用。
即使外部函数已经执行完毕、从调用栈弹出，内部函数依然可以访问外部函数的变量。

这是JavaScript实现"数据私有"的基础机制。

### 我如何理解它
**类比**：闭包就像一个函数给自己开了一扇"后门"。
函数A执行完了，按理说里面的变量都被销毁了，
但函数A内部的函数B拿着一把钥匙（引用），
随时可以通过这扇后门回去访问那些"应该已经消失"的变量。

**联想**：这让我想到React的useState——每次组件重新渲染时，
为什么state不会被重置？因为React底层用闭包来保持对state的引用。
（→ 需要进一步验证这个想法，可能写一个实验代码）

**个人经验**：做待办应用时，我原本想在全局定义一个todos数组，
所有组件直接访问。学了闭包后，我意识到应该用组件内部的state
+ props传递，这就是闭包思想的实际应用。

### 相关笔记
- 20240315-003-JavaScript作用域链
- 20240316-001-React useState的工作原理
- 20240310-007-模块化与私有变量

### 应用场景
- **待办应用**：用闭包思想管理组件内部状态，避免全局变量污染
- **未来项目**：实现计数器、缓存函数（memoization）等需要"记住状态"的功能
- **面试准备**：闭包是JS面试必考知识点，这条笔记可以直接用来复习
```

## 六、从文献笔记到永久笔记的转化流程

```
周日晚 知识清理时间
  ↓
打开本周的所有文献笔记
  ↓
逐条问自己：
  "这条笔记里的知识，是否在其他地方也出现过？"
  "这个概念，能否提炼成一个通用的原理？"
  "我是否在其他项目中也用到过类似的东西？"
  ↓
如果能提炼成通用概念 → 写成永久笔记
  - 给ID
  - 用自己的话写详细说明
  - 添加类比/联想/个人经验
  - 查找相关笔记，建立反向链接
  - 列出应用场景
  ↓
如果与某条已有永久笔记相关 → 更新那条永久笔记
  - 添加新的理解
  - 添加新的反向链接
  - 补充新的应用场景
  ↓
如果只是特定场景的一次性记录 → 保留在文献笔记中
  - 等未来有更多相关积累时再提炼
```

## 七、最低可行实践（MVP）

**不要追求写很多笔记。追求每条笔记都真的理解。**

| 要求 | 数量 | 频率 |
|------|------|------|
| 文献笔记 | 不限 | 学习时随时写 |
| 永久笔记 | 3-5条 | 每周 |
| 反向链接 | 每条至少1个 | 写永久笔记时 |

**每周只写3-5条永久笔记，不求多但求真的理解。**

一条真正理解并能复用的永久笔记，通常比大量复制粘贴的笔记更有价值；具体效果需在实际使用中验证。

## 八、常见问题

**Q：我用什么工具写卡片笔记？**
A：任何支持Markdown和内部链接的工具都可以。推荐Obsidian、Notion、或直接用VS Code管理Markdown文件。工具不重要，养成习惯才重要。

**Q：我写的笔记很烂怎么办？**
A：先写出来。烂笔记 > 没笔记。你可以在周回顾时不断修改和完善。永久笔记不是一次写定，是持续进化的。

**Q：我需要给笔记打很多标签吗？**
A：不需要。反向链接比标签更重要。标签用于分类，链接用于建立思想网络。先做好链接，标签打2-3个即可。

**Q：我可以用AI帮我写笔记吗？**
A：**先自己写，再用AI优化。** 如果你让AI代写，你跳过了"用自己的话解释"这个最关键的学习步骤。你可以写完让AI帮你改表达，但不能让AI代替你思考。

## 九、检查清单：一条合格的永久笔记

- [ ] 有唯一ID（日期+序号）
- [ ] 核心概念用一句话概括
- [ ] 详细说明是用自己的话写的，不是复制粘贴
- [ ] 包含个人理解（类比/联想/经验）
- [ ] 至少链接了1条其他永久笔记
- [ ] 至少列出了1个应用场景

> 卡片笔记的本质不是"记笔记"，而是"思考的外化"。当你被迫用自己的话解释一个概念时，你才真正理解它。当你被迫找到它与其他知识的连接时，你的知识网络才在生长。
