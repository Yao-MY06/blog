## 一、为什么你需要博客个人网站（不是可选，是刚需）

### 博客 = 你的三大变现杠杆

| 杠杆 | 说明 | 效果 |
|------|------|------|
| **求职杠杆** | HR/技术主管Google你名字时，第一个看到的是你的博客和作品 | 未知，需以真实数据验证 |
| **接单杠杆** | 客户通过技术文章找到你，信任成本极低 | 未知，需以真实数据验证 |
| **学习杠杆** | 写博客逼你真正理解知识，而不是"感觉懂了" | 未知，需以真实数据验证 |

### 博客 vs 其他平台

| 平台 | 问题 | 博客的优势 |
|------|------|-----------|
| 掘金/CSDN/知乎 | 内容被平台稀释，读者看完就关 | **你拥有域名**，读者会记住你 |
| GitHub | 只有代码，没有故事和思考过程 | 代码+文章结合，展示完整能力 |
| 朋友圈/即刻 | 碎片化，无法系统性展示 | **永久存档**，随时可引用 |
| 简历 | 静态、被动、一次性 | 动态、主动、持续更新 |

### 你的博客必须回答的问题

访客（HR/客户/同行）点进你的网站后，30秒内要得到答案：

1. **你是谁？** → 关于页的一句话定位
2. **你能做什么？** → 项目展示页
3. **你做得怎么样？** → 技术博客的深度
4. **怎么联系你？** → 清晰的联系方式/社交链接

## 二、技术选型：为什么选 Next.js + MDX

### 推荐技术栈

```
框架：Next.js 14 (App Router)
语言：TypeScript
样式：Tailwind CSS
内容：MDX（Markdown + React组件）
部署：Vercel（免费）
域名：Vercel提供的 .vercel.app 或自购域名（~70元/年）
```

### 为什么选这套

| 考量 | 理由 |
|------|------|
| **正好在你的学习路线图上** | 第9-12周学Next.js，博客就是学习项目 |
| **一举多得** | 学技术+做项目+搭博客，三件事情合为一件 |
| **MDX超能力** | 可以在文章里嵌入React组件（如交互式代码演示、数据可视化） |
| **SEO友好** | Next.js的SSG让文章能被Google收录，带来被动流量 |
| **零成本部署** | Vercel免费额度足够个人博客使用 |
| **可扩展** | 后期可以接入数据库、评论系统、访问量统计 |

### 其他方案对比（为什么没选）

| 方案 | 缺点 |
|------|------|
| Hexo/Hugo | 太"博客专用"，学不到通用前端技能 |
| WordPress | 太重，需要服务器，不符合"轻量"原则 |
| Notion + Super.so | 每月$12，且自定义空间有限 |
| 纯静态HTML | 维护成本高，每篇文章都要手动改 |

## 三、网站架构：5个核心页面

```
my-blog.vercel.app/
├── /                  ← 首页：Hero + 最新文章 + 精选项目
├── /blog              ← 博客列表：所有文章 + 标签过滤
├── /blog/[slug]       ← 文章详情页：MDX渲染 + 代码高亮
├── /projects          ← 项目展示：作品集（从GitHub同步）
├── /about             ← 关于页：我是谁 + 技能栈 + 时间线
├── /now               ← 现在页：我正在做什么（学习/项目/接单状态）
└── /uses              ← 工具页：我使用的工具配置（引流用）
```

### 页面2：博客列表（/blog）

**设计目标**：让访客快速找到感兴趣的文章

**功能**：
- 文章卡片：标题 + 摘要 + 标签 + 发布日期 + 阅读时间
- 标签过滤（React, Node.js, 学习方法, 项目复盘...）
- 搜索框（可选，后期加）

**文章分类体系**（与你的个人管理系统对齐）：

| 标签 | 对应系统模块 | 内容类型 |

| `#变现思考` | 06-机会捕获 | 怎么把技术换成钱 |

### 页面4：关于页（/about）

**设计目标**：建立信任，让访客记住你这个人

**内容结构**：
```
1. 我是谁（一句话定位）
   "大二计算机学生，全栈开发学习者，用文字和代码构建东西的人。"

2. 我的故事（3-5段，为什么学编程、现在的目标）
   - 不要写"从小就对计算机感兴趣"这种陈词滥调
   - 写真实的转折点："大一下学期突然意识到..."
   - 写现在的状态："我正在学习Next.js，目标是..."

3. 技能栈（可视化，不要只列文字）
   用进度条或标签云展示：
   - 熟练：JavaScript, React, HTML/CSS, Git
   - 学习中：TypeScript, Next.js, Node.js
   - 计划中：AI工具开发, 独立产品

4. 时间线（关键里程碑）
   2024.09 入学 → 2025.03 开始系统学习全栈
   → 2025.06 完成第一个全栈项目
   → 2025.08 赚到第一笔技术收入
   → ...（逐步填充）

5. 联系方式
   - 邮箱（用图片防爬虫，或写成 xxx [at] gmail [dot] com）
   - GitHub
   - 即刻/小红书（如果运营的话）
```

## 四、内容生产流程：与管理系统无缝对接

### 博客文章从哪里来？

```
个人管理系统2.0 → 博客内容

04-知识笔记/卡片笔记.md
  → 经过整理和扩展 → 技术博客文章

02-项目管理/[项目名]/项目复盘.md
  → 脱敏处理（去掉客户信息） → 项目复盘文章

01-日记与周期/周复盘.md
  → 提取亮点和学习收获 → 周复盘文章（精简版）

06-机会捕获/接单实录.md
  → 总结经验教训 → 接单实录文章
```

### 每周内容生产SOP

```markdown
## 周日：确定下周写什么（与周复盘同步）

□ 打开周复盘模板
□ 回答："这周我学到了什么值得分享的东西？"
□ 确定下周博客主题（1个）
□ 在`content/blog/`下创建草稿文件：`YYYY-MM-DD-草稿标题.mdx`

## 周一至周六：边学边写

□ 学习过程中记录关键点和踩过的坑
□ 直接在草稿文件中写入（不用完美，先堆料）
□ 周四前完成初稿（不用发布，先写出来）

## 周日：打磨发布（与周复盘同步）

□ 完善文章结构：问题→方案→代码→总结
□ 添加代码示例（确保可运行）
□ 检查错别字和排版
□ 添加标签和封面图
□ **发布到博客**
□ 同步到掘金/知乎/小红书（扩大曝光）
□ 在社交媒体发一条"本周新文章"（1句话+链接）
```

### 文章质量标准（发布前检查）

```markdown
□ 标题：具体、有信息量，不是"学习笔记"这种废话
  ✓ 好标题："我用Next.js做博客时踩的5个坑"
  ✗ 坏标题："Next.js学习笔记"

□ 开头：前3句话说清楚这篇文章解决什么问题

□ 代码：所有代码块都经过测试，确保复制粘贴能运行

□ 结构：有明确的小标题，不是一坨文字

□ 长度：1000-3000字为宜（太短没深度，太长没人看完）

□ 结尾：有一个明确的"下一步行动"或"思考题"

□ SEO：包含关键词（文章标题和正文中自然出现）
```

## 七、博客运营：不是写完了就完了

### 发布后的必做动作

```markdown
文章发布 ≠ 结束，而是分发和反馈的开始

□ 发布后1小时内：
  → 发一条朋友圈/即刻："写了篇关于XX的文章，1分钟速读版：XXX"
  → 附链接，不要只发链接没文字

□ 发布后24小时内：
  → 同步到掘金（全文复制，加原文链接）
  → 同步到知乎（写个精简版，引导到原博客）
  → 同步到小红书（图文版，适合技术类内容）

□ 发布后1周内：
  → 回复所有评论
  → 记录哪些渠道带来的流量最多
  → 把高互动的文章加入"精选"

□ 发布后1个月：
  → 看Google Analytics，哪些关键词带来了搜索流量
  → 根据数据调整后续文章方向
```

### 文章更新策略

```markdown
□ 技术文章：每6个月检查一次，更新过时代码
□ 项目复盘：项目有重大进展时追加更新
□ Now页：每月更新一次
□ 关于页：每季度更新一次技能栈和时间线
```

## 八、关键指标：怎么衡量博客是否成功

### 短期指标（第1-3个月）

| 指标 | 目标 | 为什么重要 |
|------|------|-----------|
| 文章数量 | ≥8篇 | 证明你有持续输出的能力 |
| 发布频率 | ≥2篇/月 | 建立读者预期 |
| GitHub提交 | 博客仓库每周有提交 | 证明你在持续迭代 |

### 中期指标（第3-6个月）

| 指标 | 目标 | 为什么重要 |
|------|------|-----------|
| 月均访问量 | ≥500 UV | 有人在看你的内容 |
| 搜索引擎流量 | ≥30% | 被动流量=被动机会 |
| 文章被转载/引用 | ≥3次 | 内容质量的外部验证 |
| 通过博客联系你的人 | ≥3人 | 博客开始替你工作 |

### 长期指标（第6-12个月）

| 指标 | 目标 | 为什么重要 |
|------|------|-----------|
| 月均访问量 | ≥3000 UV | 稳定的流量基础 |
