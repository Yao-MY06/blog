## 阶段三：苍穹外卖后端练手（2026-09-16 晚 至 2026-09-24，8 个学习日，当前 P0）

用阶段二的手册概念练习和巩固课程中的后端流程，包括认证、分层、数据库访问与业务状态流转。前端仅用于后端联调，不学习或实现界面细节；本阶段不写入简历，也不作为简历核心项目。2026-09-03 压缩为 8 个学习日（原 12 天）：压缩的是排程密度，**阶段门验收项一项不减**；某天未消化完按实际学习日顺延，不降低验收线。

### 8 个学习日顺序

| 学习日 | 只做这一组内容 | 当天结束时留下什么 |

| 1 | 跑通环境、数据库、后端启动和项目目录 | 启动方式与第一个真实报错（如有） |
| 2 | 员工登录、JWT 与拦截器；分类管理 | 登录成功及一次受保护接口调用；一组分类真实增改记录 |

## 阶段五：微服务高并发交易平台（阶段四通过后，按实际开发日顺延）

微服务高并发交易平台实施与验收计划 是本阶段范围、全部“最低必验收”、标准门与收缩门的唯一权威来源；路线图只保留摘要和阶段顺序，不独立定义或放宽验收。候选项默认不进入当前待办。

### 学习与实施范围

只承诺三个方向：有限微服务拆分；Redis Lua、MQ、幂等、失败重试、最终一致性与对账组成的秒杀链路深化；固定环境下的真实基线、慢查询与索引分析、链路追踪、错误诊断和 Docker Compose 等工程证据。每项技术必须服务于真实调用链或已验证问题。

### 三方向摘要（非标准门定义）

| 方向 | 路线摘要 | 验收入口 |
| --- | --- | --- |
| 有限微服务拆分 | Gateway、`user`、`shop/content`、`trade` 和真实跨服务调用 | 项目一 3.1 |
| 秒杀链路 | `Redis Lua -> MQ -> 数据库落库`、幂等、失败恢复与对账 | 项目一 3.2 |
| 工程证据 | Docker Compose、固定环境基线、trace、慢 SQL 与索引证据 | 项目一 3.3 |

### 二值阶段门与证据

- **标准门通过**：只有 项目一标准门 判定通过才算通过；其中三个方向各自列出的全部“最低必验收”必须全部有证据。
- **标准门未通过**：项目计划任一“最低必验收”缺证据即为未通过。上表摘要不得用作替代清单，也不得把空壳服务、配置文件、设计图或计划当成完成。
- 简历只写可复现事实；没有数据写“未知”，不写未经实测的 QPS、P99、效率或规模结果。

### 中期检查与范围冻结

在项目一实施中期严格按 项目一 4.2 中期检查与范围冻结 作决定。若关键链路、发布窗口闭合方案或剩余工时不足，则冻结为项目一规定的收缩范围；冻结后不得重新扩回标准门，也不得删除收缩门必验项。

### 目标窗口末的收缩门摘要

以下内容只摘要 项目一 4.3 收缩门；实际判定、证据要求和后续延期均以项目一计划为准。若项目一窗口结束时标准门仍未通过，按中期冻结结果停止增加广度，只保留：

- [ ] 1 条经过 Gateway 的 `trade` 真实调用链，入口、跨服务调用和结果均有证据。
- [ ] 最薄的 `Redis Lua -> MQ -> 数据库落库` 秒杀链路可运行，并能核对消息与落库结果。

## 阶段六：智能故障诊断与自动评测平台（项目一验收通过后）

只有项目一的标准门或明确改写后的收缩门通过，本阶段才成为唯一开发 P0。智能故障诊断与自动评测平台实施与验收计划 是本阶段范围、实施阶段、证据要求和最终验收的唯一权威来源；路线图只保留非穷尽摘要，不得凭本页摘要判定通过。候选项不在本路线重复展开。

### 学习与实施范围

Java/Spring Boot 承载诊断调度、Agent Loop、受限指标/日志/链路工具、证据校验、Redis 短期任务状态和 MySQL 诊断记录；模型接入层可替换。项目二以真实故障注入、ground truth 比对、循环防护、上下文压缩和自动评测为核心，具体数量、边界、失败矩阵与证据以项目二计划为准。

### 验收摘要（非阶段门）

以下只用于理解阶段重点，不是可替代的验收清单：

- 工具调用、故障注入和诊断报告必须能关联任务 ID、工具调用 ID、故障 ID、认证主体和 Java 日志；独立脚本或 mock 不能代替真实闭环。
- 身份隔离必须真实验证，包括主体间数据隔离、会话命名空间和越权拒绝，不能信任客户端自报身份。
- Redis 短期任务状态和 MySQL 长期诊断记录必须分别验证读回、过期/清理和重启后的生命周期。
- 非法参数、超时、工具失败和证据校验失败必须真实触发，并验证无副作用、无半写入、无无证据结论等二值不变量。
- 第 7 个实际开发日必须按 项目二 6.2 中期冻结 冻结继续或收缩范围；收缩切片通过也不能称完整平台完成。

最终判定只看 项目二 6.3 最终阶段门：其中全部必验项和证据通过才可称项目二完成；本摘要缺项或措辞差异均不得降低权威门。

## 串行阶段切换检查

本节只适用于六个编号学习或开发阶段，不适用于投递辅助线。阶段窗口结束时只做三项判断：

1. 当前阶段门的每个必验项是否都有指定的真实运行、调用、查询、日志或书面证据；全部满足才标“通过”。
2. 未通过项是否属于关键能力；关键能力继续补齐，非核心功能删除或明确延期。阶段 5 只能在中期按项目计划 4.2 冻结范围，并在窗口结束按项目计划 4.3 收缩门验收。
3. 下一阶段是否已成为唯一学习或开发 P0，并已把明天第一步写回当前面板。

没有可靠数据时写“未知”，不得编造 QPS、P99、效率、薪资、录用率或其他结果。候选技术的启用条件与完整清单只在对应项目计划维护。
