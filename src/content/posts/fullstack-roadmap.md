> **状态：历史参考，非活跃路线。** 当前职业路线为 [Java后端学习与投递路线图](/blog/posts/java-backend-roadmap/)。下方 React / Node 固定阶段、时长、提交频率、交付物与收益预期等均为历史参考，不作为当前任务、承诺或考核；现行执行以 Java 后端路线和 当前状态面板 为准。本页不是日常入口。


> **前提假设**：你每天有 1.5-2 小时可用于全栈学习（不包括课程作业时间）。
> 如果你连这 1.5 小时都挤不出来——先砍掉B站，再来谈学习。

## 战略定位

- **优先级**：第一优先级（生存技能）
- **目标**：16周后拥有一个可演示的全栈作品集 + 活跃的GitHub绿墙 + 3篇技术博客
- **学习方法**：项目驱动，停止刷视频教程，直接开干
- **AI使用**：每阶段有明确的AI权限边界（见下各阶段说明）
- **变现视角**：每个阶段标注"这个技能现在能换钱吗？怎么换？"

## 16周总览

```
周次    阶段名称          核心技术栈              目标项目
─────────────────────────────────────────────────────────
1-2     止血期            JS基础+环境搭建           个人主页（静态）
3-4     前端核心          React+Tailwind            待办应用前端
5-6     后端入门          Node.js+Express+MongoDB   待办应用后端API
7-8     全栈整合          前后端联调+用户认证        完整待办应用
9-12    进阶实战          TypeScript+Next.js+部署   仿写常用网站前端
13-16   作品集中锋        独立项目+博客+GitHub打磨   作品集网站
```

## 第一阶段：止血期（第1-2周）

> **目标**：建立每日编码习惯，让GitHub绿墙开始有颜色。不要小看这两周，它是整个系统的基石。

### 本周任务清单

| # | 任务 | 预估时间 | AI权限 |
|---|------|----------|--------|
| 1 | 搭建开发环境：VS Code + Live Server + Git 配置 | 2h | 绿灯：可问配置问题 |
| 2 | 用纯 HTML+CSS 写一个个人主页，包含头像、简介、联系方式 | 4h | **红灯**：必须手敲每一行 |
| 3 | 学会用 Git 提交代码，创建 GitHub 仓库，每天提交 | 1h | 绿灯：可问Git命令 |
| 4 | 学会用浏览器 DevTools 调试样式 | 1h | 黄灯：可问用法，但必须亲手试 |
| 5 | JavaScript 基础语法：变量、函数、条件、循环、数组 | 5h | **红灯**：必须手写练习 |

### 第二周任务清单

| # | 任务 | 预估时间 | AI权限 |
|---|------|----------|--------|
| 1 | JavaScript DOM 操作：用 JS 修改网页内容 | 3h | **红灯**：必须手敲 |
| 2 | 事件处理：点击、输入、表单提交 | 2h | **红灯**：必须手敲 |
| 3 | 给个人主页添加 JS 交互（如点击切换主题、动态时钟） | 4h | 黄灯：卡住了可问思路 |
| 4 | 学习 Markdown，写第一篇技术博客草稿 | 2h | 绿灯：格式可参考 |
| 5 | **周回顾**：本周 GitHub 提交天数？学到什么？卡在哪里？ | 1h | - |

### 阶段交付物检查清单

- [ ] GitHub 仓库已创建，至少有 10 次 commit
- [ ] 个人主页可通过 GitHub Pages 在线访问
- [ ] 能不看教程手写出一个包含 JS 交互的简单页面
- [ ] 写了一篇 500 字以上的技术博客草稿

### AI使用规范（本阶段）

- **禁止**：让AI直接生成你的个人主页代码
- **允许**：问"如何用JS获取当前时间"、"Git commit 命令是什么"
- **强制**：即使问了AI，也必须自己手敲一遍，不能复制粘贴

### 💰 变现视角（第1-2周）

| 问题 | 答案 |
|------|------|
| 现在能接单吗？ | **不能**。还在学基础，没有可交付的作品。 |
| 这个技能怎么变现？ | 间接变现：HTML/CSS/JS是前端接单的入门门票，学会后才能做企业官网、落地页。 |
| 预计何时能赚到钱？ | 第4-6周：做出待办应用后，可以尝试接"静态页面"小单（500-1000元）。 |

> **不要急着想赚钱**。前4周的目标是建立编码习惯和GitHub绿墙，赚钱是水到渠成的事。

| 4 | 学习 Tailwind CSS 基础：utility class 思维 | 2h | 绿灯 |
| 5 | 用 React + Tailwind 做一个静态待办列表（只显示，无交互） | 3h | 黄灯 |

### 第四周任务清单

| # | 任务 | 预估时间 | AI权限 |
|---|------|----------|--------|

### 阶段交付物检查清单

- [ ] 理解 Props 和 State 的区别，能给别人讲清楚
- [ ] 第二篇博客草稿完成
- [ ] GitHub 本周至少 5 天有提交

### 💰 变现视角（第3-4周）

| 实操建议 | 在猪八戒发布一个"React前端开发"的服务，定价从500元小单开始，积累评价。 |

## 第三阶段：后端入门（第5-6周）

> **目标**：理解"前后端分离"的本质——前端负责展示，后端负责数据。自己动手搭一个能存数据的API。

### 第五周任务清单

| # | 任务 | 预估时间 | AI权限 |
|---|------|----------|--------|
| 1 | 安装 Node.js，理解 CommonJS 模块系统 | 1h | 绿灯 |
| 2 | 学习 Express：路由、中间件、请求/响应 | 3h | 黄灯 |
| 3 | 搭建第一个 Express 服务器，`GET /` 返回 Hello World | 1h | **红灯** |
| 4 | 安装 MongoDB（本地或使用 MongoDB Atlas 免费版） | 1h | 绿灯 |
| 5 | 用 Mongoose 定义 Todo 数据模型（内容、完成状态、创建时间） | 2h | 黄灯 |

### 第六周任务清单

| # | 任务 | 预估时间 | AI权限 |
|---|------|----------|--------|
| 1 | 实现 RESTful API：`GET /todos` 获取所有待办 | 2h | 黄灯 |
| 2 | 实现 `POST /todos` 创建待办、`DELETE /todos/:id` 删除 | 2h | 黄灯 |
| 3 | 实现 `PATCH /todos/:id` 更新完成状态 | 2h | 黄灯 |
| 4 | 用 Postman/Thunder Client 测试所有 API 端点 | 1h | **红灯**：必须亲手测 |
| 5 | 写第三篇博客：《我用Express写了个API，终于理解后端是干嘛的了》 | 2h | **红灯** |

### 阶段交付物检查清单

- [ ] Express 服务器能在本地跑，`npm start` 一键启动
- [ ] 四个 API 端点都经过手动测试，知道每个返回什么
- [ ] MongoDB 里有真实数据（不是内存存储）
- [ ] 能解释"RESTful API"是什么意思，HTTP方法对应什么操作

### 💰 变现视角（第5-6周）

| 问题 | 答案 |
|------|------|
| 新增变现能力 | 可以接"前后端分离"的项目了，单价翻倍。 |
| 定价参考 | 全栈小应用（CRUD+部署）：3000-8000元；API开发：1500-5000元。 |
| 获客渠道 | 在即刻/小红书发"XX天学会全栈"的打卡帖，引流到私域接单。 |
| 关键动作 | 把待办应用改造成一个有实际场景的应用（如"家庭记账""图书管理"），作为接单作品集。 |

## 第四阶段：全栈整合（第7-8周）

> **目标**：让前端和后端"说上话"。这是全栈开发的核心能力——理解前后端如何交互。

### 第七周任务清单

| # | 任务 | 预估时间 | AI权限 |
|---|------|----------|--------|
| 1 | 学习 `fetch` API，用 React 调用后端的 `GET /todos` | 3h | 黄灯 |
| 2 | 实现前端调用后端创建待办（POST 请求） | 2h | 黄灯 |
| 3 | 实现删除和更新功能的前端调用 | 2h | 黄灯 |
| 4 | 理解 CORS 错误——你一定会遇到，学会解决它 | 1h | 绿灯 |

### 第八周任务清单

| # | 任务 | 预估时间 | AI权限 |
|---|------|----------|--------|
| 1 | 学习 JWT 认证原理（不用深究，理解流程即可） | 2h | 黄灯 |
| 2 | 实现用户注册/登录 API（用户名+密码） | 3h | 黄灯：可参考模式 |
| 3 | 前端添加登录页面，登录后存储 token | 2h | 黄灯 |
| 4 | 未登录用户重定向到登录页（路由守卫概念） | 2h | 黄灯 |
| 5 | **里程碑**：部署到 Render/Railway/Vercel，让朋友能访问 | 2h | 绿灯 |

### 阶段交付物检查清单

- [ ] 完整的全栈待办应用，前后端分离但能协同工作
- [ ] 有用户注册/登录功能（哪怕只是基础实现）
- [ ] 部署到公网，URL 可以发给朋友
- [ ] 能解释前后端是怎么通信的（HTTP请求→API→数据库→返回数据）

### 💰 变现视角（第7-8周）

| 问题 | 答案 |
|------|------|
| 新增变现能力 | **完整全栈开发能力**，可以独立接中小型项目。 |
| 定价参考 | 企业官网全栈：5000-2万元；SaaS MVP：1万-5万元。 |
| 关键动作 | 注册码市/程序员客栈，完善个人资料+作品集链接。开始投标小项目。 |
| 目标 | **第8周结束前，必须发出第一单投标**——哪怕不中，也要开始参与市场。 |
